# Device verification

> Audience: administrators verifying the Home Assistant bot device with Element.
>
> Language: [English](DEVICE_VERIFICATION.md) | [中文](DEVICE_VERIFICATION.zh.md)

Device verification confirms that `Home Assistant matrix_e2ee` in Element is your Home Assistant bot device. A successful verification makes Element and the bot trust each other's devices.

## Before you start

- Install the [Element](https://element.io/) Matrix client on a phone or desktop.
- Have the bot's Matrix account and password ready, for example `@ha-bot:example.org`.
- Confirm that `matrix_e2ee` is configured in Home Assistant and connected.

When you first log in to the bot account with Element, follow its prompt to set up a security key or recovery method. Store the recovery key safely. This bootstraps the account's cross-signing identity and may need to be repeated if secure storage is reset.

## Recommended: use the Home Assistant wizard

In the recommended workflow, Element initiates verification. The Home Assistant wizard never starts a transaction itself; it waits for the request, displays the emoji, and submits your decision. Bot-initiated verification remains available through the advanced service interface.

1. In Home Assistant, open **Settings → Devices & Services → Matrix E2EE → Configure → Verify device**.
2. Keep the waiting page open.
3. Log in to the bot account in Element and open **Settings → Sessions**.
4. Find the device named `Home Assistant matrix_e2ee` and choose **Verify**. Its device ID is generated by the Matrix server and is not fixed.
5. Element and Home Assistant display a set of emoji. Compare every emoji in order.
6. If they match, choose **They match** in Home Assistant. If they differ, choose **They do not match** and cancel the verification.
7. Wait for Home Assistant to report that verification is complete. Element should also show the device as verified.

A successful SAS verification establishes mutual trust: Element trusts the bot device, and the bot trusts the current Element device. Devices are not trusted automatically, even when they belong to the same Matrix account.

## Advanced: confirm through Developer Tools

If the wizard is unavailable, you can complete the same flow through Home Assistant Developer Tools:

1. Listen for `matrix_e2ee_verification` under **Developer Tools → Events**.
2. Start verification from Element.
3. When `stage: sas` arrives, compare the event's `emojis` with Element.
4. If they match, call `matrix_e2ee.confirm_verification` with the event's `transaction_id`.
5. If they differ, call `matrix_e2ee.cancel_verification` with the same event's `transaction_id`.
6. A `stage: done` event means verification completed.

If you already received `stage: canceled` or `stage: timeout`, that `transaction_id` is no longer valid. Start a new verification from Element instead of confirming the old transaction.

## Fallback: establish local trust by fingerprint

Use fingerprint verification only when SAS emoji verification is unavailable. It establishes one-sided local trust, not a complete SAS verification.

1. Listen for `matrix_e2ee_fingerprint` under **Developer Tools → Events**, then call `matrix_e2ee.get_fingerprint`. Read the bot's `ed25519` fingerprint from the event.
2. In Element, choose manual verification for the bot session and compare the fingerprint character by character over a trusted channel.
3. To make the bot trust another device, call `matrix_e2ee.verify_device_by_fingerprint` with its `user_id`, `device_id`, and `ed25519` fingerprint.

Fingerprints are case-sensitive. Trust is established only on an exact match; otherwise `matrix_e2ee_error` emits `fingerprint_mismatch`.

## Troubleshooting

| Symptom | Action |
|---|---|
| The bot device is missing | Confirm that the integration is connected; search Element sessions for `Home Assistant matrix_e2ee` |
| `verification_peer_denied` | Initiate from the bot's own account or a user allowed by `verification_peer_users` |
| `verification_timeout` | The 4-minute window expired; start again from Element |
| `invalid_transaction` | Use the `transaction_id` from the latest verification event |
| The emoji differ | Cancel immediately, check the account and target device, then retry; investigate account or transport compromise if it persists |
| The device ID changed after restart | The crypto store may have been lost; treat it as a new device and verify again |
| `session_corrupt` / `restore_failed` | Delete the session file (and store if inconsistent), remove the integration, add it again, then re-verify |

The session and crypto store must persist with the Home Assistant configuration directory. Restoring the same store preserves the device ID and verification state across restarts.
